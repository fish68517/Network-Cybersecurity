# 第一阶段第二轮业务流程验证记录

## 1. 验证目标

验证当前第一阶段原型是否已经具备以下完整业务能力：
- 系统初始化与密态状态保存
- 管理员注册患者/医生账号
- 管理员维护患者档案
- 医生查看患者档案并新增、修改病历
- 患者查看本人档案和本人病历
- 异常处理：管理员删除仍有关联病历的患者档案时被拒绝

- 项目根目录：`D:\Acode\Android\complete\MedicalSystemDemo`
- Visual Studio：2019 Community
- SGX SDK：`D:\Software\SGX_SDK`

## 4. 端到端验证流程

### 步骤 1：初始化系统
- 启动程序
- 执行系统初始化
- 自动创建默认管理员账号：`admin / admin123`
- 成功写出密态状态文件

### 步骤 2：管理员业务
- 使用 `admin / admin123` 登录
- 注册患者账号：`patient1 / pat123`
- 注册医生账号：`doctor1 / doc123`
- 为 `patient1` 新建患者档案
- 查看用户列表
- 查看患者列表
- 管理员退出登录

### 步骤 3：医生业务
- 使用 `doctor1 / doc123` 登录
- 查看患者列表
- 查看 `patient1` 患者档案
- 为 `patient1` 新增病历
- 查询 `patient1` 病历列表
- 修改病历 ID `1`
- 再次查询 `patient1` 病历列表，确认修改生效
- 医生退出登录

### 步骤 4：异常处理验证
- 管理员重新登录
- 尝试删除 `patient1` 患者档案
- 因该患者仍有关联病历，系统拒绝删除
- 返回错误：`患者仍有关联病历，不能删除档案`
- 管理员退出登录

### 步骤 5：患者业务
- 使用 `patient1 / pat123` 登录
- 查看本人档案
- 查看本人病历
- 确认医生修改后的病历内容可见
- 患者退出登录

### 5.3 输出验证结论
当前第一阶段原型已完成从“系统初始化 -> 账户注册 -> 建档 -> 建立病历 -> 修改病历 -> 患者查看 -> 异常拦截 -> 密态保存”的闭环验证。

## 6. 当前可用于答辩展示的能力

当前系统已经可以展示以下答辩要点：
- 敏感业务逻辑运行在 SGX Enclave 中
- 病历与患者档案支持分角色访问控制
- 病历数据支持密态持久化保存
- 管理员不可绕过业务规则强行删除仍有关联病历的患者档案
- 患者只能查看本人信息与本人病历
- 医生可以完成病历新增与修改
