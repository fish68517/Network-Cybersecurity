# 项目运行环境配置说明

## 1. 文档目的

本文档用于说明“基于 Intel SGX 的密态病历信息系统”在 Visual Studio 中成功编译、运行所需的软件环境、环境变量、项目路径要求和实际操作步骤。

本文档面向两种场景：
1. 答辩现场直接双击 `exe` 运行
2. 答辩现场在老师电脑或本机中通过 Visual Studio 重新编译并运行

当前项目已经按 **SGX Simulation 模式** 验证通过，因此 **不要求答辩机器必须具备 SGX 硬件和驱动**。只要软件环境配置正确，即可运行演示。

## 4. 必须配置的环境变量

### 4.1 核心环境变量
必须配置系统环境变量：

- 变量名：`SGXSDKInstallPath`
- 变量值：`D:\Software\SGX_SDK\`

注意：变量值最后建议保留反斜杠 `\`。

### 4.2 配置方法
可用“系统属性 -> 高级 -> 环境变量”手动配置。

也可以使用管理员命令行执行：

```bat
setx SGXSDKInstallPath "D:\Software\SGX_SDK\" /M
```

配置完成后，建议：
- 重新打开 Visual Studio
- 重新打开命令行窗口

## 5. 项目对路径的特殊要求

这是最关键的一点。

本项目虽然使用了 `SGXSDKInstallPath`，但在两个工程文件中 **仍然存在若干硬编码路径**，目前写死为：

- `D:\Software\SGX_SDK\...`

因此，如果老师电脑上的 SGX SDK 不安装在 `D:\Software\SGX_SDK\`，则仅设置环境变量还不够，还需要修改工程文件中的硬编码路径。

### 5.1 需要检查的文件
- `D:\Acode\Android\complete\MedicalSystemDemo\MedicalSystemDemo\MedicalSystemDemo.vcxproj`
- `D:\Acode\Android\complete\MedicalSystemDemo\MedicalSystemDemo_app\MedicalSystemDemo_app.vcxproj`

### 5.2 修改原则
如果 SGX SDK 安装在其他目录，例如：
- `C:\Intel\SGX_SDK\`

则需要在以上两个 `.vcxproj` 文件中，将所有：
- `D:\Software\SGX_SDK\`

统一替换为：
- `C:\Intel\SGX_SDK\`

### 5.3 建议做法
为了降低答辩现场风险，最稳妥的做法是：
- 直接把答辩机器上的 SGX SDK 安装到 `D:\Software\SGX_SDK\`
- 同时设置 `SGXSDKInstallPath=D:\Software\SGX_SDK\`

这样可以避免现场逐个修改工程文件。

## 6. Visual Studio 中的推荐运行方式

### 6.1 打开解决方案
打开：
- `D:\Acode\Android\complete\MedicalSystemDemo\MedicalSystemDemo\MedicalSystemDemo.sln`

本项目最稳的构建顺序如下：

1. 先构建 `MedicalSystemDemo` 项目
2. 再构建 `MedicalSystemDemo_app` 项目

这是当前解决方案文件中的正常映射，不是错误。

### 6.5 设置启动项目
在 Visual Studio 中将以下项目设置为启动项目：
- `MedicalSystemDemo_app`

### 6.6 运行成功后的输出位置

Enclave 输出：
- `D:\Acode\Android\complete\MedicalSystemDemo\MedicalSystemDemo\x64\Simulation\MedicalSystemDemo.signed.dll`

宿主程序输出：
- `D:\Acode\Android\complete\MedicalSystemDemo\MedicalSystemDemo_app\x64\Debug\MedicalSystemDemo_app.exe`

## 8. 程序首次运行时的正确表现

首次运行时，如果没有历史密态数据，正常表现应为：
- Enclave 初始化成功

## 10. 常见问题排查

### 10.1 提示找不到 SGX 头文件或库文件
原因：
- SGX SDK 未安装
- `SGXSDKInstallPath` 未设置
- 工程中的硬编码 SDK 路径与实际安装路径不一致

处理：
- 先确认 `SGXSDKInstallPath`
- 再检查两个 `.vcxproj` 中的 `D:\Software\SGX_SDK\` 是否需要替换

### 10.2 Enclave 初始化失败
原因通常为：
- `MedicalSystemDemo.signed.dll` 未生成
- 宿主程序输出目录缺少 `MedicalSystemDemo.signed.dll`
- 输出目录缺少 SGX Simulation 相关 DLL

处理：
- 先确认 Enclave 项目已成功生成
- 再确认 `MedicalSystemDemo_app` 输出目录中存在：
  - `MedicalSystemDemo.signed.dll`
  - `sgx_urts_simd.dll`
  - `sgx_uae_service_sim.dll`
  - 以及其他随 SDK 拷贝的 Simulation DLL

### 10.3 程序能启动但没有历史数据
这是正常情况。
如果是第一次运行，直接选择：
- `1` 初始化系统

### 10.4 老师电脑路径不同导致工程打不开或编译失败
最稳妥处理方式：
- 尽量把项目目录和 SGX SDK 目录保持与当前机器一致

推荐保持为：
- 项目目录：`D:\Acode\Android\complete\MedicalSystemDemo`
- SGX SDK：`D:\Software\SGX_SDK\`

如果无法保持一致，则需要：
- 修改 `.vcxproj` 中的硬编码路径
- 重新打开解决方案后再编译

## 11. 答辩现场建议

为了避免现场风险，建议准备两套方案：

### 方案 A：直接运行已打包 exe
优点：
- 成功率最高
- 不依赖现场开发环境

### 方案 B：通过 Visual Studio 现场编译运行
优点：
- 可以向老师证明项目可二次构建

建议答辩时优先采用：
1. 先展示打包版可以直接运行
2. 若老师要求，再打开 Visual Studio 按本文档重新编译运行
