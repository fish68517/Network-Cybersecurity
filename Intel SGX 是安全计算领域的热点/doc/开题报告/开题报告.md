## 一、选题的背景与意义

### 背景
随着信息技术的飞速发展，电子病历（Electronic Medical Record, EMR）系统已成为现代医疗体系的核心。电子病历极大地提升了医疗服务的效率和质量，但同时也带来了前所未有的数据安全挑战。病历信息作为公民最敏感的隐私数据之一，一旦泄露，不仅会侵犯患者隐私权，还可能被用于欺诈、勒索等非法活动，造成严重的社会危害和经济损失。

目前主流的数据保护技术主要集中在「**静态保护**」（at-rest）和「**传输中保护**」（in-transit）：
- 静态保护：通过磁盘加密防止物理设备丢失导致数据泄露；
- 传输中保护：通过 SSL/TLS 等协议确保网络传输不被窃听。

然而，这两种技术都忽略了关键的「**使用中保护**」（in-use）。当数据被加载到内存进行处理时（如医生查询病历、系统做数据分析），必须以明文形态存在。此时数据完全暴露在操作系统、虚拟机管理器甚至特权管理员面前。攻击者可通过内存抓取、缓冲区溢出、恶意软件或管理员后门等方式直接窃取明文病历。

传统安全模型假设操作系统和管理员可信，但在云环境和复杂系统中，这一假设已越来越脆弱。因此，如何保护「使用中」数据，抵御特权软件和物理攻击，已成为信息安全领域的迫切需求。

近年来，可信执行环境（Trusted Execution Environment, TEE）在医疗数据保护与机密计算领域的应用受到广泛关注。现有研究主要形成以下技术路线：
- **TEE 与密码学融合**：同态加密（HE）、安全多方计算（MPC）与 TEE 结合；
- **面向医疗数据的 TEE 系统**：支持密文检索、时间序列数据端到端保护等；
- **性能优化与工程实践**：Switchless 调用、跨平台兼容性等。

**可信执行环境（TEE）** 是基于硬件的安全解决方案，在 CPU 内部创建隔离的「飞地」（Enclave），其代码和数据对外部（包括 OS、管理员、物理探针）完全加密隔离。**Intel SGX** 是目前最具代表性的 TEE 实现，支持远程证明（Remote Attestation）和数据密封（Sealing）。

### 意义

**理论意义**
- 实现数据全生命周期密态保护，填补「使用中」环节安全空白；
- 将信任根从庞大 OS 缩小到几百 KB 的 Enclave + CPU 硬件，大幅减少攻击面；
- 为 TEE 在医疗敏感数据场景的工程化应用提供参考与验证。

**现实意义**
- 从根源杜绝因服务器被入侵、管理员恶意或系统漏洞导致的核心病历泄露；
- 强力满足《网络安全法》《数据安全法》《个人信息保护法》等合规要求；
- 提供「数据可用不可见」承诺，提升医患信任，推动远程医疗与医疗大数据发展。

## 二、研究的基本内容与拟解决的主要问题

### 基本内容
构建基于 **Intel SGX** 的密态病历管理系统，实现从用户认证到数据操作的全程密态处理，即使系统被攻破，明文病历永不泄露。

1. **多用户身份定义与安全认证**
   - 角色：患者（对自己信息读写、对病历只读）、医生（对患者信息只读、对病历读写）、管理员（仅部署，无法接触业务数据）
   - Enclave 内实现基于 RSA/ECC 的公钥认证 + Challenge-Response，无口令明文传输

2. **患者基本信息密态管理**
   - Enclave 内使用安全数据结构（如 STL Map 或自定义安全链表）暂存解密后明文
   - Enclave 内强制执行细粒度访问控制

3. **患者病历信息全生命周期密态处理**
   - 密态 CRUD：所有操作通过加密 ECall 传入，仅在 Enclave 内解密处理，处理完立即重新加密输出（明文不落地）
   - 数据完整性：引入 MAC 或版本号防篡改/重放
   - 性能优化：采用 **Switchless Calls**，通过共享内存环形缓冲区大幅降低高频 ECall/OCall 开销

### 拟解决的主要问题
1. **密态环境下的系统安全性与密钥保护**
   - 远程证明建立可信链，防止伪造 Enclave
   - Sealing 机制实现安全持久化存储
   - Enclave 内密钥全生命周期安全管理

2. **TEE 性能瓶颈**
   - 传统 ECall/OCall 上下文切换开销大
   - 在不牺牲安全前提下，通过 Switchless 等技术使系统性能接近原生可用性

## 三、研究的方法与技术路线

### 项目概述
C/S 架构，基于 Intel SGX SDK，使用 C/C++ 在 Linux (Ubuntu) 平台开发。

### 研究方法
1. 文献分析法
2. 原型迭代法（Hello World → 密钥管理 → 业务逻辑 → 性能优化）
3. 实验测试法（功能 + 性能对比实验）

### 技术路线与系统架构

**核心技术路线**
1. 安全基础：远程证明 + Sealing
2. 密钥管理：在 Enclave 内生成、管理各级密钥
3. 性能优化：Switchless Calls + 共享内存缓冲区
4. 权限控制：Enclave 内基于数字签名强制访问控制

### 技术选型

| 层面         | 核心技术                  | 作用与优势                                      |
|--------------|---------------------------|-------------------------------------------------|
| 硬件安全     | Intel SGX                | 硬件级隔离，保护代码和数据免受特权软件攻击      |
| 开发框架     | Intel SGX SDK            | 完整工具链，支持编译、签名、远程证明等          |
| 编程语言     | C/C++                    | 系统级控制，适合高性能安全应用                  |
| 操作系统     | Linux (Ubuntu)           | 稳定支持 SGX                                    |
| 密码学库     | OpenSSL / SGX-SSL        | 标准加密算法实现                                |
| 性能优化     | Switchless Calls         | 大幅减少上下文切换开销                          |
| 数据存储     | SGX Sealing              | 只有合法 Enclave 才能解密数据                  |
