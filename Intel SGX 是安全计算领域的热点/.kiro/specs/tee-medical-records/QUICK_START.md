## 🏗️ 系统架构（简化版）

```
客户端 ──HTTPS──> 服务器 ──ECall/OCall──> Enclave ──> 数据库
                                  ↑
                            (所有敏感数据处理)
```

**关键特点**
- 所有敏感数据在 Enclave 内处理
- Enclave 外的数据全部加密
- 即使 OS 被攻破，数据仍安全

## 🚀 快速开始（5 步）


## ⚠️ 常见陷阱

| 陷阱 | 解决方案 |
|------|---------|
| SGX 硬件不支持 | 使用 SGX 模拟器（`export SGX_MODE=SW`） |
| Enclave 内存溢出 | 使用外部内存、实现分页机制 |
| 性能不达标 | 使用 Switchless Calls、实现缓存 |
| 密钥泄露 | 确保密钥仅在 Enclave 内生成 |
| 权限绕过 | 在 Enclave 内强制执行权限检查 |

## 📈 开发建议

### ✅ 推荐做法
- 按阶段逐步开发，不要跳步
- 每个模块完成后立即编写单元测试
- 定期进行安全审计
- 保持代码简洁和可维护性
- 及时记录设计决策

### ❌ 避免做法
- 不要一次性实现所有功能
- 不要忽视测试
- 不要在 Enclave 外处理明文数据
- 不要使用弱加密算法
- 不要忽视性能优化
